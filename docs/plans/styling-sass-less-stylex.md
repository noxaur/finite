# Sass, Less and StyleX support

Finite writes every hand edit in the project's styling convention (`apps/server/src/source/`). Today that's Tailwind, CSS modules (`*.module.css` only) and inline styles. This plan adds Sass and Less as dialects of the CSS-modules convention, and StyleX as a fourth convention.

## Decisions

1. **Sass and Less aren't new conventions.** The `Styling` enum keeps `css-modules`; the dialect comes from each sheet's file extension. A project can mix `.module.css`, `.module.scss` and `.module.less`.
2. **Round-trip parsing and printing with PostCSS syntaxes.** `postcss-scss` for `.scss`, `postcss-less` for `.less`, plain `postcss` for `.css`. One helper in `source/css.ts` returns the syntax for a file. Every caller parses with it and prints with `root.toString(syntax)`, because the default stringifier drops `//` comments and Less mixins. That covers `editRule`, `readTokens`, `writeToken` and `hasToken`, which now take the file name. Tests prove that an edit leaves the rest of the file byte-identical, and that the result still compiles with `sass` and `less`.
3. **Indented Sass (`.sass`) is refused.** No maintained round-trip parser exists. A `.module.sass` import makes a style edit refuse with `unsupported-style` and a message saying why and what to do.
4. **Nesting.** `editRule` still edits the top-level `.name` rule, or appends one when the class appears nowhere in the sheet. If the class appears only in nested or compound selectors (`.list { .card {} }`, `&__title`, `.a .card`), the edit refuses with `unsupported-style`, because a new top-level rule wouldn't win. This applies to `.css` modules too.
5. **Values are written raw.** No mapping to `$vars`/`@vars` in v1. If the declaration already uses one, the edit replaces it with the literal value, as CSS modules do today with `var()`.
6. **Tokens in Sass/Less projects** are CSS custom properties, read from and written to the global sheets in `design.css` (which may now be `.scss`/`.less`). `$vars` and `@vars` aren't tokens in v1. A new light token goes in `@theme` only when the design is Tailwind. Otherwise it goes in the first `:root` rule, or a new one placed after any `@use`, `@forward` and `@import`. This also fixes inline and CSS-modules designs, which get a `@theme` block today.
7. **StyleX is a new convention, `stylex`.** It's added to `Styling` in `packages/protocol/src/model.ts`.
8. **StyleX edits change the `stylex.create` object in the same file.** For `<div {...stylex.props(styles.card, active && styles.on)}>`, Finite edits the `card` entry of the top-level `const styles = stylex.create({...})`. The target is the last unconditional `X.key` argument. If a later argument that Finite can resolve (`active && styles.on`) sets the same property, the edit refuses, because the change wouldn't show. Later arguments it can't resolve, like a passed-in `style` prop, are ignored. Keys are camelCase (custom properties quoted). Values are written as strings. If the property's value is a conditional object (`{ default: …, ":hover": … }`), Finite sets `default` and leaves the other branches alone. If `default` is itself an object, the edit refuses. `null` deletes a scalar property, or sets `default: null` in a conditional object. The import can be the namespace (`import * as stylex`) or named (`import { create, props }`), under any local name.
9. **StyleX refusals.** The edit refuses with `unsupported-style` when: the styles object comes from another file; the entry is built from code (a spread, a function, a dynamic style); there's no unconditional argument; or the file has more than one `props` spread on the element. The message names the reason and says to ask the agent.
10. **An element without `stylex.props` gets inline `style`.** This matches CSS modules on an element without `className`. Adding a new `create` key is v2.
11. **Detection.** StyleX wins when `@stylexjs/stylex` is a dependency, at least one file imports it and calls its `props` (under any local name), and those files are at least as many as the files with `className=` strings. StyleX is checked before Tailwind. Otherwise the current rules apply (Tailwind, CSS modules, inline). Module detection keeps counting `.module.(css|scss|sass|less)`, so a `.sass` project reaches the refusal in decision 3. Existing designs keep the `styling` stored in `.finite/design.json`. The docs say to edit it, or reconnect, to switch.
12. **StyleX tokens (`defineVars`) are out of scope for v1.** The Tokens page shows the CSS custom properties in `design.css`, as it does for inline projects. Inspector token picks send `var(--name)`, which doesn't map to StyleX's hashed variables. v2 reads `*.stylex.ts` `defineVars` and writes `tokens.name` references.
13. **The StyleX Vite plugin is the project's own.** Finite adds nothing. StyleX's unplugin (pinned at 0.19.x in the fixture) is `enforce: "pre"` with a plain transform hook, so Finite's hook-level `order: "pre"` stamp runs first. The fixture must prove that the stamped locs and revs match the file on disk, that styles show and update over HMR, and that `.finite/` prototypes compile. React Router framework mode with StyleX is out of scope for v1.

## Surfaces

| Surface                                           | Sass/Less                                                                                                                                                                                                                                                                                                            | StyleX                                                                                     |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Hand edit (style)                                 | `css.ts` syntax, `imports.ts` `cssModules` matches `.module.(css\|scss\|less)`                                                                                                                                                                                                                                       | new `source/stylex.ts`, dispatch in `rewrite.ts` `style()`                                 |
| Other edits (text, move, remove, duplicate, attr) | unchanged                                                                                                                                                                                                                                                                                                            | unchanged                                                                                  |
| Undo, concurrent edits                            | span patches, unchanged; test undo on a `.scss` edit                                                                                                                                                                                                                                                                 | test undo on a `create` edit                                                               |
| Detection                                         | `detect.ts`: scan `.scss/.less`, `entryCss` accepts them                                                                                                                                                                                                                                                             | `detect.ts` `detectStyling`                                                                |
| Tokens                                            | parse global `.scss/.less` sheets                                                                                                                                                                                                                                                                                    | unchanged (v2)                                                                             |
| Export zip                                        | `localImports` follows `@import`/`@use`/`@forward` in `.scss` and `@import` (with options like `(reference)`) in `.less`. Bare specifiers (`@use 'tokens'`) resolve relative to the sheet, with Sass partials (`_tokens.scss`) and `index`/`_index`. `url()` assets still follow. No load paths or custom importers. | follows TS imports already                                                                 |
| `candidates()`                                    | treat `.scss/.less` like `.css` (no extension guessing)                                                                                                                                                                                                                                                              | —                                                                                          |
| Agent                                             | the `Styling:` line already says `css-modules`; instructions mention `.module.scss/.less`                                                                                                                                                                                                                            | `Styling: stylex`; instructions tell it to use `stylex.create` and not `className` strings |
| Fixtures                                          | new `apps/server/fixtures/sass` (React Router SPA, `.module.scss` and `.module.less`, `sass` and `less` deps)                                                                                                                                                                                                        | new `apps/server/fixtures/stylex` (React Router SPA with `@stylexjs/unplugin`)             |
| Docs                                              | `docs/how-finite-works.md` CSS-modules section, README, AGENTS.md "Every styling convention"                                                                                                                                                                                                                         | same, with the new convention                                                              |

## Work split

- **Executor A (Sass/Less):** `css.ts`, `tokens.ts`, `imports.ts`, `index.ts` (`localImports`, sheets), `detect.ts` (`sourceFiles`, `entryCss`, module regex), `apps/server/package.json`, the `sass` fixture, tests, docs for CSS modules.
- **Executor B (StyleX):** `model.ts` `Styling`, new `stylex.ts` + tests, `rewrite.ts` `style()` dispatch and the `conventions` test list, `detect.ts` `detectStyling` only, `agent/instructions.ts`, the `stylex` fixture, docs for StyleX.
- Both edit `detect.ts` and the docs; the orchestrator merges them.
- Then verify in the real app with `verify-finite` on both fixtures: a style edit, a batched multi-select edit, a second edit through the remapped selection, undo and redo around another actor's edit, a prototype edit and the `outside-prototype` refusal, each `unsupported-style` refusal, and a regression pass on a blank design and the existing fixtures.
